# 交付管线部署与飞书集成方案

## 一、部署方案

当前版本采用 Docker Compose 部署，包含 React 前端、NestJS API、PostgreSQL 和 Redis。PostgreSQL 保存台账和日志，Redis 作为后续飞书通知、Base 回写和异步任务队列。

生产环境建议部署在阿里云 ECS 内网环境，通过 Nginx 提供 HTTPS 和域名访问。后续流量增大后，可以把 PostgreSQL 迁移到阿里云 RDS，把 Redis 迁移到阿里云 Redis，并让应用容器横向扩容。

## 二、飞书集成思路

第一层接入飞书 OAuth。当前本地已经实现 mock 登录、session cookie 和用户表；正式环境关闭 mock 后，通过飞书 OAuth 获取用户 open_id、姓名、部门和邮箱。

第二层接入飞书通讯录。需求负责人、需求人、关注人、解决方案负责人等人员字段从手填文本升级为企业通讯录选择，保存 open_id，页面展示姓名。

第三层接入飞书 Base。需求提交写入提需求表，交付台账读取和更新总表；状态变更、负责人变更和关注人变更后续可以同步回飞书 Base。

## 三、监控与通知

系统提供 `/healthz` 和 `/metrics`，可接入 Nginx、Prometheus 或云监控。业务通知后续可通过飞书机器人或飞书消息发送给需求负责人、需求人、关注人和管理员群。
